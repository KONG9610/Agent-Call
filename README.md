# Agent Call

让 AI 完成工作后，用桌上的真实 IP 话机打电话提醒你。

Windows 桌面窗口 + 托盘。支持固定播报文案、Edge 网络音色、Windows 本地音色、任务筛选和顺序拨号。无需另外购买语音 API；Codex 本身仍需要用户自己的可用账号或配置。

> **当前版本：0.1.1，Windows x64 预览版。** 已验证话机为 Yealink SIP-T21P E2（固件 52.82.0.20）。其他型号需要适配和测试，不能承诺“任何 IP 电话下载即用”。

## 桌面界面

采用浅色圆角卡片和侧边导航。语速、音调、音量通过滑块调整，旁边实时显示数值；音量 100% 表示默认音量。点击“恢复默认”重置声音参数，再点击“保存设置”生效。可先用“电脑试听”听效果。Windows 本地语音仅支持语速，音调和音量滑块在该模式下禁用；切换 Edge 在线语音可使用全部参数。响铃时长也可通过滑块设置。

## 两种 AI 的接入方式不同

| 来源 | 怎么触发 | 是否依赖模型记忆 |
|---|---|---|
| **Codex** | 程序读取本机 Codex 新增的 `task_complete` 完成事件，一轮结束自动入队 | 不依赖 |
| **WorkBuddy** | AI 根据记忆/提示，主动执行 `PhoneService.exe --call --source workbuddy` | **依赖；AI 忘记调用就不会来电** |

WorkBuddy 当前没有在本项目中接入可靠的系统级完成通知。它的开关只能允许或拒绝主动调用，不能保证 AI 每次都执行。不要把它宣传成与 Codex 相同的自动完成通知。其他脚本也可显式执行上述入口。

Codex 接入目前使用**本地任务记录格式适配器**，不是官方承诺稳定的公共 API。已在本机桌面版记录中核实 `event_msg/task_complete`。Codex 升级、记录位置或格式变化后需要重新检查。程序不覆盖 `~/.codex/config.toml` 的 `notify`，可以与已有通知工具共存；不用重启 Codex来接入。

## 下载后怎样用

1. 从 GitHub **Releases** 下载 `AgentCall-0.1.1-windows-x64.zip`，完整解压到你有写权限的目录。不要只拿走一个 EXE。源码 ZIP 是给开发者/AI 使用的，不是直接运行的发布包。
2. 双击 **`AgentCall.exe`**。无需自行安装 Python。需要 Windows 10/11 x64 和系统的 .NET Framework 4.8。程序不开机自启。
3. 首次连接话机：**把下面的“给 AI 的配置提示”交给你的 AI**，让它读取同目录 `AI_SETUP.md`，按现场网络配置。
4. 在“声音与播报”编辑文案，选择音色并保存，点击“拨打一通测试”。
5. 选择“所有 Codex 任务”或“仅选定任务”，打开左下角通知开关。

**首次启动默认关闭通知。** 开关和其他设置保存在程序旁边 `data/`；再次启动恢复设置。窗口左上角的红色关闭按钮只隐藏到托盘；从托盘菜单“退出程序”才会停止监听和内置电话服务。退出不再补打待处理通知，重启不回放旧完成事件。

### 给 AI 的配置提示（可直接复制）

```text
请帮我配置 Agent Call。先读取解压目录里的 README.md 和 AI_SETUP.md，
检查电脑系统、程序运行状态、Codex 数据目录、局域网地址、防火墙和话机型号。
我的目标是 Codex 每轮完整回复结束后，真实话机响铃并播报固定文案。
请复用现有配置，避免重复启动 SIP 服务；不要覆盖我的 Codex notify 设置。
只有缺少话机地址、管理密码、可用账号或网络信息时再问我。
如果我使用 WorkBuddy，请明确说明它依赖记忆/提示主动调用，并配置相应调用指令。
做完要测试真实通话和一次真实 Codex 完成事件，区分“入队”“拨通”“我听到声音”。
```

## 哪些配置不能省略

代码和依赖可以打包，但每个人的**电脑地址、话机地址、账号以及网络权限**不一样。这些需要首次配置，AI 可以代做大部分操作。

| 配置 | 谁来处理 |
|---|---|
| Python、语音依赖 | Windows 发布包自带 |
| Codex 接入 | 自动找 `CODEX_HOME`，否则使用用户目录下 `.codex`；可在窗口更改 |
| 话机接电、插网线 | 用户完成；电脑和话机需要局域网互通 |
| 话机注册服务器 | 填当前电脑的局域网 IP，UDP 5060（以程序设置为准） |
| 话机账号 | 建议使用空闲账号，分机 1001，避免覆盖现有办公电话账号 |
| 音频 | 需要 G.711 PCMA/PCMU；局域网直连无需公网端口映射 |
| 自动接听 | 不同品牌/固件不同，按兼容说明验证；不支持时可选手动接听 |
| Windows 防火墙 | “连接设置 → 配置防火墙”；需要管理员权限，只开放专用网络的本地子网 |
| 多网卡或 VPN | AI 核实实际局域网 IP，必要时填入“电脑局域网 IP” |
| IP 变化 | 建议在路由器保留电脑地址，否则需要更新话机服务器地址 |

只做来电播报**不需要 VB-CABLE、faster-whisper、FFmpeg**。通过电话说话输入到对话框属于后续功能，不包含在本次桌面发布版中。

## 使用规则

- **只在完整一轮结束时提醒**：进度消息、工具输出和正在思考不会触发。短回复也触发。
- **排队**：多个任务依次完成，逐通拨号，不同时抢同一台话机。
- **去重**：同一个任务、同一轮完成记录只处理一次。
- **范围**：任务列表显示最近最多 300 项；勾选后点击保存。历史任务名称取自本机 Codex 数据；读取失败时可以检查 `session_index.jsonl` 或让 AI 排查。
- **关闭开关**：取消待拨自动通知；已经响铃或接通的电话可能继续结束。关闭期间的事件不会在重新开启后补打。
- **手动测试**：明确点击“拨打一通测试”会绕过通知开关，用来检查电话链路。
- **失败**：在“通知记录”显示原因，不自动无限重拨。失败不会阻塞后续通知。
- **子代理**：带 subagent 标记的子任务记录不单独通知，避免一个父任务多次响铃。
- **重启**：离线期间不补发；未完成队列被取消，避免重启时电话突然密集响起。
- **复用旧服务**：检测到本机 8080 上兼容的 Vibe Phone，会复用它。此时接听模式等底层设置以旧服务为准；迁移到内置服务前应由 AI 确认并停止旧服务，不要同时占用 5060。

## 文案和音色

默认文案为作者个人口令“高书记，我已经按照你的指示完成了工作。”，请改成适合自己的内容。

- Windows 本地语音：离线，音色取决于系统已装语音。
- Edge 网络语音：提供多种语言和声音，支持语速、音调、音量；新文案需联网。使用 `edge-tts` 的非官方接口，上游变化可能导致失效。失败时可切换本地语音。
- 可以手填 Edge 音色名，例如 `zh-CN-YunxiNeural`。
- 试听和电话都使用 8 kHz 电话音质，不代表原始合成音频的高保真效果。
- 固定文案会缓存；修改文案或音色后重新生成。缓存仅存在本地 `data/cache/`。

## WorkBuddy 配置

在“通知来源与任务”点击“复制 WorkBuddy 提示”，交给 WorkBuddy 保存到它自己的记忆/项目说明。实际调用命令为：

```powershell
& '<你的解压目录>\PhoneService.exe' --call --source workbuddy
```

必须先运行桌面程序，并开启总开关和 WorkBuddy 开关。返回 `QUEUED` 只表示入队，实际结果看窗口；`SKIPPED` 表示用户关掉通知，AI 不应自行打开；`ERROR` 表示未运行或连接异常。

**这不是 WorkBuddy 的系统完成钩子。** 它仍取决于模型是否记得调用。固定脚本可以在任务结束时明确执行这条命令，获得程序级确定性。

兼容原 Vibe Phone：内置电话服务运行时，在本机 `127.0.0.1:8080` 保留 `GET /status` 和 `POST /notify`。旧 `say.py` 的 `source=agent` 归到 WorkBuddy 开关，所有来电进入顺序队列。为了保证窗口设置为准，旧请求的文案、音色和目标分机以当前窗口设置为准，不接受逐通覆盖。该兼容入口只供本机 JSON 脚本使用，拒绝带浏览器 Origin 的写请求。旧网页控制台已由桌面窗口替代。

## 话机兼容范围与屏幕名称

| 型号/类型 | 状态 |
|---|---|
| Yealink SIP-T21P E2，52.82.0.20 | 已有真实响铃、自动接听、播放、挂断验证 |
| Fanvil / Grandstream / 其他标准 SIP 话机 | 未在本发布版逐款验证，需适配自动接听 |
| SIP 软件电话 | 可用于协议调试，具体应用未逐一验证 |
| 模拟座机、仅支持专有协议或被运营商锁定的设备 | 不保证直接接入 |

程序的“来电名称”和话机的“线路标签/账号显示名称”是不同设置。改变来电名称不会自动改话机待机屏幕。话机自己的用户名/注册名保持分机号，例如 1001；标签可以叫 `codex`。

**服务用于可信局域网，不要把 SIP/RTP 暴露到公网。** 当前 SIP 注册没有账号密码鉴权。桌面控制接口只绑定回环地址，并使用本地随机访问令牌；为旧脚本保留的 8080 接口没有令牌，但也仅绑定回环地址，不应代理到外网。

## 让 AI 排障

详细步骤见 [AI_SETUP.md](AI_SETUP.md)，适配范围见 [COMPATIBILITY.md](COMPATIBILITY.md)。

- 窗口：话机是否注册、监听目录是否存在、队列和最近事件。
- 本地日志：`data/logs/app.log`，循环保留，错误可定位网络/音色/注册问题。
- 设置：`data/settings.json`；通知队列：`data/queue.sqlite`。
- 控制地址和令牌：`data/runtime.json`，只在运行时存在，**不要上传**。
- `data/` 可能含个人任务标题/ID、网络设置和音频缓存，不应公开提交。
- 诊断任务是只读检查，不要擅自删别人的服务、重置整台话机或开放公网端口。

## 开发与打包

Windows x64、Python 3.13、.NET Framework 的 C# 编译器。建议在 D 盘项目目录构建：

```powershell
python -m venv .build-venv
$env:PIP_CACHE_DIR = "$PWD\.build-cache"
$env:TEMP = "$PWD\.build-tmp"
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
& .\.build-venv\Scripts\python.exe -m pip install -r requirements-build.txt
& .\build.ps1
```

测试：`python -m unittest test_app -v` 和 `python selftest.py`。前者检查完成事件、排队、去重、开关和任务筛选；后者使用模拟 SIP 话机，不会拨真实设备。

架构：`Desktop.xaml` / `DesktopWpf.cs` 是 WPF 桌面界面和托盘；`app_service.py` 管理服务、队列和本地控制接口；`monitor.py` 只读监听 Codex；`pbx.py` / `sipcore.py` / `rtp.py` / `g711.py` 复用原 Vibe Phone 的电话实现；`voice.py` 提供两套语音。`PhoneService.exe --phone-ip <IP>` 提供可供 AI 使用的 Yealink 账号检查入口，详情见 AI_SETUP。
